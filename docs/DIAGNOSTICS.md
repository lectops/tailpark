# Connection timeline

Open **Settings → Connection timeline** to inspect the local connection recorder. Refresh reads the saved app history and, when reachable, imports the helper's observations. Export saves a plain-text file through Android's document picker. Nothing is uploaded automatically. Clear removes app history and requests removal of helper history. If the helper is offline, a durable pending-clear marker blocks old helper history from being imported until that removal succeeds.

When saved prior sessions or recovery observations exist, the main screen also shows a concise explanation on the next launch. Tap it to open the same timeline. This is a view of retained observations, not a declaration that an outage occurred every time the app was stopped.

The timeline records observed ACC and screen changes, parked-controller phases, Android VPN tunnel and Tailscale backend states, selected network transport, helper availability, recovery attempts and outcomes, helper sessions, watchdog availability and observed watchdog PID changes. The detached helper separately listens for changes in the available non-VPN network inventory, so network observations can continue while the app process is dead. An available transport is not proof that the internet or tailnet is reachable. A denied or unsupported callback reports unknown; a missing callback does not establish that all networks are gone.

Android boot counts and received boot/shutdown broadcasts are evidence of those specific observations. A shutdown broadcast does not prove shutdown completed. App/helper session IDs, event sequence numbers, app/helper build versions, wall timestamps, elapsed realtime and boot counts are retained. Within a known boot, elapsed realtime provides ordering even if the wall clock changes. When the boot count is unavailable, the recorder cannot reliably compare monotonic times across processes or restarts.

Events with unknown boot counts retain their saved/import order. Backwards wall-clock changes and recreated helper journals with reset sequence numbers cannot reorder those sessions; no cross-process outage ordering is inferred from them.

A new session with no recorded stop for the previous session is displayed as **Recording stopped; cause unknown**. It does not establish a reboot, power loss, firmware kill, or continuous connectivity. The final event can be lost if a process crashes or electrical power disappears; writes are not synchronously flushed to physical storage on every observation. The concise explanation describes recorded event ordering, not an inferred root cause. For example, a network-loss observation followed by a recovery attempt in the same known boot can be described in that order; it does not establish why the network disappeared.

The app and helper each retain at most 384 events and 96 KiB of journal data, plus a small journal-identity file. Rotation drops a batch of older events to avoid rewriting a full journal for every new event. Repeated identical states are deduplicated, the app's pending observation queue is bounded, and there is no new periodic polling. Helper history is imported in bounded pages during the existing helper exchange; an explicit Refresh can also import history. Gaps from rotation are reported when a previously imported cursor falls behind retained history. Existing `last-status.json` and `previous-status.json` snapshots are preserved unchanged.

The record format permits only fixed event/value enums, build versions and timing/session metadata. It does not accept exception messages, shell output, authentication tokens, helper secrets, peer names, IP addresses, SSIDs, filenames of transferred files or other application logs. The helper's files remain in its shell-owned private runtime directory, and app history remains in app-private storage. Export is always an explicit user action. An exported file is independent of local history, so clearing the recorder does not remove files you previously exported.

Host regression tests cover state deduplication, bounds and paging, rotation, abrupt restarts, partial writes, corrupt/oversized input, import idempotence, helper journal recreation, clear cursor/session behavior, boot-count changes, wall-clock changes, unknown recording gaps, graceful stops and allowlisted serialization. JVM tests cannot validate DiLink callback permissions or real power transitions. On the head unit, verify network loss while the app is killed, recovery history, reboot retention, explicit export, clear while the helper is disconnected, and absence of credentials/identifiers in the exported file.

The inactivity timer records its confirmed expiry as a parked-access event. That observation does not establish that firmware subsequently slept or powered off the head unit. An expired helper recovery request is acknowledged as terminal and does not trigger the cold-activity recovery fallback.
